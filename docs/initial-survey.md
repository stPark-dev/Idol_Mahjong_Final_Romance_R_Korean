## 2. 파일 구성 (ISO9660, 63개)

- 실행 코드: `1ST.BIN`(상주, `0x06004000`)만. 화면 흐름은 `1ST.BIN` 안에 있다(§2.1).
- `SL.BIN`: 상점·대국 단계에 들어갈 때 `0x06060000`에 읽는 대국용 그림 묶음(패·점수판 등 VDP1 스프라이트 원본). 동영상 프레임 버퍼와 같은 자리라 동영상 뒤에는 다시 읽는다.
- `SHOP.BIN`, `YAKU.BIN`, `GAME05/09/12/14/15.BIN`, `KISEKAE.BIN`: **음악(사운드 RAM `0x25A0B000`에 읽는 곡 데이터)**. 1차 조사의 "프로그램 후보"는 틀림. 표 `0x060126B0`(이름, 크기, 곡 번호), 로더 `0x060125A4(번호)`.
- 화면 데이터(압축 없음, 파일 바이트가 VRAM에 그대로 들어감): `SHOPDAT`(상점), `MJDAT1–3`(대국 배경·공용), `PROFDAT`(프로필), `CONTIDAT`(이어하기), `ENDDAT`(엔딩), `ALBDAT`(앨범), `OPTDAT`(옵션), `KISEDAT`·`KISE_RI`·`KISE_KA`(옷 갈아입히기, `kisedat.bin`은 소문자 이름으로 읽음).
- 동영상 26개: `{AS,KE,MI,RI,RY}{OP,01–04}.CPK` (+`RY05`). FILM 1.06, Cinepak 320×224, 소리 포함.
- `CDDA1–15`: ISO 항목이 2–16번 오디오 트랙을 가리킴.

### 2.1 화면 흐름 (`1ST.BIN`)

- 최상위 `0x0600D870`: 0 초기화 → 1 `SL.BIN` 읽고 주 루프 → 주 루프가 2를 돌려주면 동영상 묶음(`0x0600F360`), 3이면 옷 갈아입히기(`0x0601A49C`).
- 주 루프 `0x06011BD0`, 상태 바이트 `0x060D7E70`(0–18): 4 프로필(데모), 5 옵션, 6 앨범, 7→옷 갈아입히기, 10 상점, 11 첫 동영상(01) 준비, 12–14 대국, 15 동영상 묶음으로(다음 상태 `0x060D50F4`, 묶음 종류 `0x060D57BC`), 16 이어하기, 17 엔딩.
- 동영상 묶음 종류: 0 대국 승리 뒤(단계+1번, 마지막 단계면 끝까지), 1 데모(OP), 2 첫 만남(01), 3 앨범(한 캐릭터 전부). RY04 표 항목의 플래그로 RY05가 이어서 나온다.
- 동영상 뒤 다음 화면: 대국(14), 상점(10), 엔딩(17, 5명 모두 이긴 뒤), 앨범(6), 프로필(4, 데모).

## 4. 텍스트 위치

- 평문 문자열 없음. 화면 글자는 모두 그림 데이터이고, 데이터 파일은 압축 없이 VRAM에 그대로 들어간다(상점 `SHOPDAT`→VDP2 `0x00100–0x0A900`·`0x20100–`, 대국 `MJDAT1`→VDP2 `0x20100–0x34700`, `SL.BIN`→VDP1 등, 256바이트 단위 대조).
- 따라서 한글화는 글꼴·인코딩이 아니라 **그림 교체**(같은 크기·색표 안에서 다시 그리기, 필요하면 배치 표 수정)다. 프로필 한마디처럼 글자 칸을 차례로 찍는 화면은 칸 표와 칸 그림을 함께 바꾼다.
- 동영상 대사: 글자 창 없이 음성만(자막 경로 §7).

## 7. 동영상 자막 경로 (2026-10-13, 세이브 스테이트 PoC로 확인)

### 7.1 재생 코드 (`1ST.BIN`, `0x06004000` 적재, SGL 사용)

- 동영상 이름 표 `0x0600F964`: 캐릭터 5명(RI, MI, KE, RY, AS 순) × 6칸 × {이름 포인터, 플래그}. 연속 재생 `0x0600F4AC(시작, 끝, 캐릭터)`가 표 항목마다 재생 함수 `0x0600F50C`를 부른다(리터럴 `0x0600F504`, 호출 1곳).
- 재생 함수 `0x0600F50C`: Cinepak 핸들 생성 `0x0600F794` → 루프 { 작업 `0x060264D8`, 표시 시각이면(`0x06026898`) 프레임 `0x06060000`→VDP1 VRAM `0x10000` 복사(`0x06005D60`), `slSetSprite(0x060E1D34, Z=170)`(`0x06005E20`), **`slSynch`(`0x06004052`, 리터럴 `0x0600F5E4`, 이 함수에서 1곳)**, 표시 완료 `0x060268E8` } → START(패드 `0x0800`) 또는 상태 5(끝)까지.
- 버퍼: 프레임 `0x06060000–0x06083000`, CD 스트림 `0x06083000–0x060B5000`, 작업 `0x060B5000–0x060B8190`, 소리 사운드 RAM `0x25A20000`(64KB). 오버레이(`SL.BIN`·`GAME*.BIN` 등, `0x06060000` 적재) 자리를 쓰므로 재생은 상주 코드에서만 일어난다.
- 시각: 루프의 r8 = 핸들, `*핸들` = 상태 구조체(`0x060B5000`). **`+0x58` = 현재 재생 시각(1/600초)**, `+0x44` = 표시한 프레임 수, `+0x38` = 상태(4 재생, 5 끝). RI01 끝에서 17,975(29.96초)·720프레임으로 동영상 길이(30.0초, 24fps)와 맞음.
- 화면: VDP1 지역 좌표 원점 (176,120), 352×240. 동영상은 x −160…159, y −112…111(위아래 8줄 검은 여백). 자막은 동영상 아래쪽에 겹친다.

### 7.3 PoC (세이브 스테이트 수정, 디스크 변경 없음)

- 코드 `tools/poc/`(gcc 14 `khsub` 컨테이너, 248바이트): `slSynch` 리터럴을 연결 코드로 바꾸고, 연결 코드는 r8(핸들)로 시각을 읽어 해당 줄이 있으면 `slSetSprite`로 4비트 색표 모드 스프라이트(PMOD `0x88`, Z=100)를 하나 등록한 뒤 `slSynch`로 넘어간다.
- 상점 세이브 스테이트에 코드(`0x06058100`)·그림(VDP1 `0x70000`)·색표를 넣고 RI01 재생 → 시험 문구 6줄이 받아쓰기 시각대로 동영상 위에 나오고, 대사 없는 구간에서는 사라짐(`docs/poc-subtitle-ri01.png`). 재생 뒤 대국 화면 정상.
- 확인 못 한 것: 디스크에서 연결 코드·자막 데이터를 싣는 경로(`1ST.BIN` 늘리기 또는 재생 직전 파일 읽기), 동영상별 줄 선택(재생 함수가 받는 이름 포인터 r4), 다른 화면의 VDP1 VRAM 사용, 실기.

### 7.4 디스크에서 싣기 (2026-10-13, 시험 디스크 `--subtitles ja`)

| `0x0600F3E0` | `0x0600F604` (스트림 초기화) | `0x06058090` | 동영상 묶음 시작 전, CD가 한가할 때 `ZSUB.DAT`를 게임 함수 `0x0600DDB8`로 VDP1 VRAM `0x40000`에 바로 읽음 |
| `0x0600F504` | `0x0600F50C` (재생 함수) | `0x06058078` | 동영상 이름(앞 4글자)으로 VRAM 안 목록에서 그 동영상의 줄 표를 RAM으로 복사 |
| `0x0600F5E4` | `0x06004052` (`slSynch`) | `0x06058080` | 매 표시 프레임 재생 시각으로 해당 줄 스프라이트 등록 |

- 확인(Mednafen): BIOS가 늘어난 `1ST.BIN`을 끝까지 읽음(RAM의 상주 코드·리터럴이 디스크와 같음). 첫 동영상 묶음(RIOP → RI01)에서 RI01 자막이 받아쓰기 시각대로 나오고 두 줄 나눔도 정상(`docs/testdisc-ja-ri01.png`), 끝난 뒤 대국 화면 정상.
- **실패한 첫 설계**: 동영상마다 자막 파일(`Z<이름>.DAT`)을 재생 함수 입구에서 읽게 했더니, 첫 자막 동영상의 생성 함수(`0x0600F794` → `0x06026A04`) 안에서 멈췄다(상태 0, 화면 검정). 그 시점에는 묶음 시작에서 연 CD 스트림(`0x0600F604`)이 살아 있어, 그 사이에 일반 파일 읽기를 끼워 넣은 것이 원인으로 보인다(스트림을 열기 전에 읽도록 바꾸자 해결 — 원인 자체를 따로 증명하지는 않음).
- 대기 시간: 상점을 나간 뒤 첫 동영상 화면까지 검은 화면이 원본 약 1.25초, 시험 디스크 약 2.0초(0.25초 간격 촬영). 묶음 200KB를 읽는 데 약 0.75초가 더 든다. 그림을 2비트로 저장하면 절반 정도로 줄일 수 있다.
- 아직 못 본 것: 대국에서 이긴 뒤의 묶음(RI02–04 등), 묶음 종류 3(`0x0600F48C`, 한 캐릭터 동영상 전부), 다른 캐릭터, 옷 갈아입히기·엔딩 화면의 VDP1 VRAM 사용(자막 묶음이 `0x40000–0x71000`을 덮음), 실기.

## 8. 시험 디스크 실행 확인 (2026-10-14, 한국어 시험 디스크 `de83daf3…`)

- 방법: 상점 세이브 스테이트에서 `0x0600F3A8`(묶음 종류 2의 분기 표 값)을 종류 3으로 바꾸고 `0x060D00A7`에 캐릭터 번호를 넣어, 상점을 나가면 그 캐릭터의 동영상 전부(OP, 01–04, 료코는 RY05까지)가 이어서 나오게 했다(에뮬레이터 안의 시험 조작, 디스크 변경 없음). 0.36초 간격으로 화면을 찍어 자막 줄(흰 글자 + 검은 테두리)이 바뀔 때마다 모았다(`work/subs.py`).
